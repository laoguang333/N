Anime 模块数据库设计

目标是把本机视频库做成长期可维护的索引：视频文件可以消失、移动、重新出现，但评分、观看进度和历史不应因为一次扫描而丢失。

软删除 扫描不到文件只标记 missing，不物理删除记录。
观看数据独立 进度和历史独立于文件存在状态，缺失视频仍能保留记录。
轻量扫描 扫描只看文件系统元信息和 ffprobe 元信息，不读取完整视频。
默认可用列表 首页默认隐藏缺失文件，历史页和缺失筛选仍可查看。

表结构

视频索引和文件状态
字段类型用途

titleTEXT展示标题，通常来自文件名 stem
file_pathTEXT UNIQUE当前规范化绝对路径，缺失时保留最后路径
original_file_pathTEXT NULL首次入库路径，为后续移动识别留余地
extensionTEXT扩展名，小写保存
folder_tagTEXT NULL相对库根的一级或分组目录
sizeINTEGER文件大小，用于变化检测
mtimeINTEGER文件修改时间，用于变化检测
duration_secondsREAL NULLffprobe 读取的视频时长
containerTEXT NULL封装格式
video_codecTEXT NULL视频编码
audio_codecTEXT NULL音频编码
width / heightINTEGER NULL分辨率
ratingINTEGER NULL1-5 星，可清除
file_stateTEXTavailable 或 missing
last_seen_atTEXT最近一次扫描确认文件存在的时间
missing_sinceTEXT NULL首次发现文件缺失的时间
missing_reasonTEXT NULL第一版可固定为 not_found
created_at / updated_atTEXT记录创建和更新时间

anime_progress

每个视频的当前观看进度
字段类型用途
video_idINTEGER PK/FK一视频一条当前进度

percentREAL播放百分比，限制在 0..1
duration_secondsREAL NULL保存时看到的视频总时长
versionINTEGER进度版本，用于调试和并发覆盖判断
updated_atTEXT最近保存进度时间

anime_watch_history

每次观看会话记录
字段类型用途
idINTEGER PK历史记录主键
video_idINTEGER FK关联视频
started_atTEXT观看开始时间
ended_atTEXT NULL观看结束时间
last_position_secondsREAL结束或离开时的位置
watched_secondsREAL实际播放累计时长，由前端累计

关系图

anime_videos.id 1 : 0..1 anime_progress.video_id 当前进度
anime_videos.id 1 : N anime_watch_history.video_id 观看历史
无 ON DELETE CASCADE 扫描缺失不删除视频，因此进度和历史不会被级联删掉。
物理清理延后 后续如果需要，再做显式“清理缺失记录”操作。

文件状态流

available

扫描确认文件存在。首页默认展示，可播放，可更新元信息。

→

missing

扫描发现文件不在原路径。保留评分、进度、历史，首页默认隐藏。

→

available

文件重新出现，清空缺失字段，计入 restored。

设计思考

为什么不物理删除

  • 视频库可能在移动硬盘、同步盘或临时挂载目录里，一次扫描不到不代表用户想删除记录。
  • 观看进度和历史比文件索引更有长期价值，误删会破坏用户信任。
  • 软删除让 UI 可以默认保持干净，同时保留恢复和人工清理空间。

为什么进度和历史分开

  • anime_progress 是“继续播放”所需的当前状态，每个视频最多一条。
  • anime_watch_history 是行为记录，一次观看一条，用于历史页面和最近观看分析。
  • 分开后不会为了展示历史而污染当前进度，也不会因为更新进度丢失历史细节。

为什么不用完整 hash

  • 视频文件通常很大，扫描阶段读取完整内容成本高。
  • 第一版只需要判断“路径对应文件是否变化”，size + mtime 足够。
  • 移动识别可以后续用轻量指纹增强，不阻塞主功能。

为什么保留 original_file_path

  • 它不是第一版必须使用的字段，但对后续“移动文件识别”和“显示最初来源”有用。
  • 保留这个字段不会增加扫描成本。
  • 如果后续确认不需要，可以不在 UI 展示。

核心 SQL 草案

CREATE TABLE anime_videos (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    file_path TEXT NOT NULL UNIQUE,
    original_file_path TEXT,
    extension TEXT NOT NULL,
    folder_tag TEXT,
    size INTEGER NOT NULL,
    mtime INTEGER NOT NULL,
    duration_seconds REAL,
    container TEXT,
    video_codec TEXT,
    audio_codec TEXT,
    width INTEGER,
    height INTEGER,
    rating INTEGER CHECK (rating IS NULL OR (rating >= 1 AND rating <= 5)),
    file_state TEXT NOT NULL DEFAULT 'available'
        CHECK (file_state IN ('available', 'missing')),
    last_seen_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ', 'now')),
    missing_since TEXT,
    missing_reason TEXT,
    created_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ', 'now')),
    updated_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ', 'now'))
);

CREATE TABLE anime_progress (
    video_id INTEGER PRIMARY KEY,
    position_seconds REAL NOT NULL DEFAULT 0,
    percent REAL NOT NULL DEFAULT 0,
    duration_seconds REAL,
    version INTEGER NOT NULL DEFAULT 1,
    updated_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ', 'now')),
    FOREIGN KEY(video_id) REFERENCES anime_videos(id)
);

CREATE TABLE anime_watch_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    video_id INTEGER NOT NULL,
    started_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ', 'now')),
    ended_at TEXT,
    last_position_seconds REAL NOT NULL DEFAULT 0,
    watched_seconds REAL NOT NULL DEFAULT 0,
    completed INTEGER NOT NULL DEFAULT 0,
    FOREIGN KEY(video_id) REFERENCES anime_videos(id)
);
